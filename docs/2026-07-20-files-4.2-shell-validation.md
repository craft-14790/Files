# Files 4.2 shell fixes - validation note

Validated on 2026-07-20 with the `FilesDev` 4.2.0.0 x64 Debug package.

- **Send to (#18707):** The local machine populated the submenu both before and after the patch, so the issue-specific empty state could not be reproduced here. The menu path was traced through `ShellContextFlyoutHelper` to `ContextMenu.EnumMenuItems`. The patch retries `WM_INITMENUPOPUP` with a zero menu position only when the normal initialization returns no string items. After rebuilding, the submenu opened with Bluetooth, Desktop, Documents, drives, and other registered destinations.
- **Windows Terminal (#18709):** Compared with #18085, which proposed hiding the command when Terminal is unavailable. The launch fix instead sets `UseShellExecute` to `false` for `wt.exe`, matching the upstream fix in #18728. Windows Terminal 1.24 and its `wt.exe` alias are installed on this machine, but Windows Terminal is not explicitly selected as the default terminal, so Files currently follows its `cmd.exe` fallback path.
- **Sidebar and Home icons:** Applied the upstream sidebar icon set and copied its scale-qualified assets into the loose Debug output. After rebuilding, Home appeared in the tab, breadcrumb, and sidebar; Pinned, Drives, Cloud Drives, Network, WSL, and Tags also rendered.
- **FilesDev shell icons:** The manifest and `resources.pri` contain the Dev `Square44x44Logo` and `StoreLogo` candidates, but the PRI-indexed PNG files were absent from the loose Debug layout. Added an after-build target that copies AppTiles PNGs without adding duplicate PRI inputs. The target completed successfully, and representative Start/taskbar assets in the registered layout matched their source SHA-256 hashes.
- **QuickLook preview:** Files already probes QuickLook before PowerToys Peek. The requested `QuickLook.exe` was running, its named pipe accepted the same toggle message used by Files, and the attached image path was sent successfully. No source change or hard-coded machine path was required.

Build command:

```powershell
MSBuild.exe src\Files.App\Files.App.csproj -p:Configuration=Debug -p:Platform=x64 -m -v:minimal -clp:ErrorsOnly
```

Result: succeeded with exit code 0.
